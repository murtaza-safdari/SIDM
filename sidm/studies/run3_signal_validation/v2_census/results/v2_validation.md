# v2 Run 3 SIDM signal census (EXONanoAOD, outputs_v2/)

Population: every file under `/store/group/lpcmetx/SIDM/run3_samplegen/outputs_v2/<era>/` for the five eras (EOS listing) and every chunk in the production DAGs (the `VARS` lines of the column and grid DAGs). One census row per file: `v2_census.csv.gz`; this report is written by `report.py render` from the files in `results/` alone. Expected configuration: `expected_config.json`, parsed from `production/chain_job_v2.sh` (md5 a3af76b526123b1a6999308a8230b9e0; identical to the copy in each of the 10 era DAG folders of the LPC submission), with the HLT menu and vertex smearing its `HLT` and `BS` settings select in each era's release on cvmfs.

Two-site production: the campaign was submitted twice with the same `chain_job_v2.sh`, DAG node names, `VARS` lines and output names, writing to the same EOS directory: the LPC submission (LPC HTCondor; its records are the `.cksum` files in the production's `condor_v2/` directory at LPC) and the CERN lxplus submission (CERN HTCondor; its `.cksum` records were supplied as one file). Each job writes one record (`production/chain_job_v2.sh`): `skip size=…` when the chunk is already on EOS at job start (the check at its lines 59-62, made only when the job starts), otherwise `adler32=… size=…` after its upload (line 234). The census joins both sites' upload records to every file (columns `lpc_*`, `lx_*`). A chunk with an upload record at both sites was produced and uploaded at both; the upload overwrites (`xrdcp -f`, line 227), so EOS should hold the later one, and the other site's record no longer matches it. That the later upload is the one kept is inferred from the overwrite flag and the matches below, not read from a log.

Checks per file: in the EOS listing with the measured size; opens with uproot and every basket of every Events branch decompresses; Events entries = NEV = Runs genEventCount; adler32 of the copied file = EOS server checksum; size and adler32 equal an upload record of either site, when one exists; provenance as configured; identity (generator record against the name, see below).
