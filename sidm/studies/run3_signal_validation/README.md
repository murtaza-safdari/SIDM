# Run 3 signal validation

`era_fingerprint.py` checks, from the content of the LLPNanoAOD files alone, that the private Run 3 production is at 13.6 TeV and that each era carries its own conditions. It reads the 200 GeV / 1.2 GeV / 4.8 mm point of both channels (120 chunks, 100k events per sample and era). sqrt(s) is computed as m(chi chibar)/sqrt(x1 x2), cross-checked against twice the beam energy from the LHE incoming partons, and compared with the generator `comEnergy`. It also measures the pileup profile, the generated and reconstructed vertex positions, and the HLT branch content. The global tag, CMSSW release and HLT menu of every processing step are read from the file's `ParameterSets` and `MetaData` trees, matching PSet IDs by MD5. Two maps show the era-specific dead regions: the 2022EE ECAL endcap region (e/gamma efficiency of gen electrons, 2Mu2E) and the 2023BPix pixel sector (mean number of tracker layers with hits of matched muons). Both use exclusive greedy matching: closest pair first, each reco object used once, and photons linked to an electron left out of the e/gamma pool. The dark-photon lepton pairs are collimated, so closest-object matching let one reco object count for both leptons. Every quoted region number (threshold, flagged-bin and rectangle averages, bin counts, BPix PF-muon efficiency and its extent at 0.5/0.75/1.0 layers, both matchings) is in `era_fingerprint_regions.json`, and the exclusive values are also in the CSV rows. Usage: `python era_fingerprint.py` (default `--eras 2022,2022EE,2023,2023BPix,2018`; `2018` is the v10 4Mu reference at 13 TeV, and a run over a subset of eras updates only those rows) writes `era_fingerprint.csv` (one row per era), `era_fingerprint.npz` (the histograms; add `--replot` to redraw without EOS) and vector PDFs in `figures/`. The m/sqrt(x1 x2) estimator has a ~2.5% low tail, which is not a beam-energy effect: about 98% of events are c-cbar initiated (2022 4Mu, four chunks), and in the tail events the low-x (x < 1.1e-3) charm parton's mass is not negligible. The LHE estimate has no such tail (99.8% of events within 13598.6-13600.6 GeV). `notebook_figures.py` makes the AN versions of the notebook's three gen-level draft figures (`run3_ctau_representative`, `run3_ctau_grid`, `run3_vs_2018_gen`; inputs cached in `notebook_figures.npz`, `--replot` to redraw). The 180-point cτ scan behind `run3_ctau_grid` is a standalone LHE+GEN job with 500 events per point, run with 2022 conditions (SampleFactory `sidm_run3_production/gen_validate_job.sh`); it does not read the produced samples.

**2018 generator-level requirement (corrected 2026-11).** The 2018 v10 production kept only events in which all four dark-photon leptons have pT > 5 GeV and |eta| < 2.4 (decay vertex V_xy < 740 cm, |V_z| < 960 cm). Earlier comparisons emulated it as pT > 1 GeV per lepton, reading the 1.1 GeV minimum of the stored 2018 leptons as the floor (that minimum is radiation after the filter). That let Run 3 events the 2018 sample would have dropped into the "in acceptance" denominators. `notebook_figures.py` now applies the requirement per event. In `run3_lj_eff.py`, `GEN_PT` is 5.0 and the vertex cuts are added to `gen_acc_mask`. The `lj_eff_geom_<era>.json` files were regenerated with these denominators, from the first 12 Run 3 chunks per point (6000 events; 5550 for 2022EE 2Mu2E_800GeV_5p0GeV_5p0mm) and 25 v10 files. The `lj_eff_real_<era>.json` files have not been regenerated and still carry the pT > 1 denominators. `ctau_all_samples.py` measures the proper cτ on every produced sample (180 points x 4 eras, from the LLPNanoAOD GenPart vertices) and writes `ctau_all_samples.csv` and `figures/run3_ctau_all.pdf`.

**Stored precision.** In nano, GenPart_mass is stored with 8 mantissa bits (0.5 GeV steps at 200 GeV, so 34 GeV steps in m/sqrt(x1 x2)) and Generator_x with 14, in both the Run 3 and the 2018 files. The sqrt(s) median is therefore quoted to the storage step, and no width column is given (it would measure storage and line shape). Provenance columns are recorded per process: VtxSmeared, comEnergy and the HLT menu are read from the process that carries them. The generator process's VtxSmeared is compared with the stored GenVtx mean and width (`vtx_pull_*`). In 2018 the only VtxSmeared is in the GEN process (SigmaZ 3.5 cm), while the stored GenVtx_z width is 3.20 cm, so its check reads MISMATCH; the Run 3 eras agree. Every row carries the git commit it was made with (`code_commit`).
