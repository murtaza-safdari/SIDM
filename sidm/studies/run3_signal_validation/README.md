# Run 3 signal validation

`era_fingerprint.py` checks, from the content of the LLPNanoAOD files alone, that the private Run 3 production is at 13.6 TeV and that each era carries its own conditions. It reads the 200 GeV / 1.2 GeV / 4.8 mm point of both channels (120 chunks, 100k events per sample and era). sqrt(s) is computed as m(chi chibar)/sqrt(x1 x2), cross-checked against twice the beam energy from the LHE incoming partons, and compared with the generator `comEnergy`. It also measures the pileup profile, the generated and reconstructed vertex positions, and the HLT branch content. The global tag, CMSSW release and HLT menu of every processing step are read from the file's `ParameterSets` and `MetaData` trees, matching PSet IDs by MD5. Two maps show the era-specific dead regions: the 2022EE ECAL endcap region (e/gamma reconstruction efficiency per dark photon to e+e-, 2Mu2E: at least one electron or photon, all objects, within Delta R < 0.1 of either electron, both electrons pT > 5 GeV and 1.5 < |eta| < 3.0, filled at the dark photon's eta, phi) and the 2023BPix pixel sector (mean number of tracker layers with hits of matched muons). The muon map uses exclusive greedy matching: closest pair first, each reco object used once. The per-object exclusive e/gamma map is kept in the npz, JSON and CSV (`ee_obj_excl_*`), with photons linked to an electron left out of its pool. Its plateau sits near 0.6 because the collimated pairs mostly resolve into a single object. Every quoted region number (threshold, flagged-bin and rectangle averages, bin counts, BPix PF-muon efficiency and its extent at 0.5/0.75/1.0 layers, both matchings) is in `era_fingerprint_regions.json`, and the exclusive values are also in the CSV rows. Usage: `python era_fingerprint.py` (default `--eras 2022,2022EE,2023,2023BPix,2018`; `2018` is the v10 4Mu reference at 13 TeV, and a run over a subset of eras updates only those rows) writes `era_fingerprint.csv` (one row per era), `era_fingerprint.npz` (the histograms; add `--replot` to redraw without EOS) and vector PDFs in `figures/`. The m/sqrt(x1 x2) estimator has a ~2.5% low tail, which is not a beam-energy effect: about 98% of events are c-cbar initiated (2022 4Mu, four chunks), and in the tail events the low-x (x < 1.1e-3) charm parton's mass is not negligible. The LHE estimate has no such tail (99.8% of events within 13598.6-13600.6 GeV). `notebook_figures.py` makes the AN versions of the notebook's three gen-level draft figures (`run3_ctau_representative`, `run3_ctau_grid`, `run3_vs_2018_gen`; inputs cached in `notebook_figures.npz`, `--replot` to redraw). The 180-point cτ scan behind `run3_ctau_grid` is a standalone LHE+GEN job with 500 events per point, run with 2022 conditions (SampleFactory `sidm_run3_production/gen_validate_job.sh`); it does not read the produced samples.

**2018 generator-level requirement (corrected 2026-11).** The 2018 v10 GEN process carries the filter as `genfilter` (GenParticleSelector on genParticlesForFilter) with the cut `(abs(pdgId)==11 || abs(pdgId)==13) && abs(eta)<2.4 && (vertex.rho<740. && abs(vertex.Z)<960.) && pt>4. && isLastCopy() && isPromptFinalState() && fromHardProcessFinalState()`, followed by `gencount` (CandViewCountFilter, minNumber 4). `gen_requirement.py` emulates it on the nano GenPart table: status 1 with the isPrompt, fromHardProcess and isLastCopy statusFlags (the post-FSR final-state copies), pT > 4 GeV, |eta| < 2.4, rho < 740 cm, |z| < 960 cm, at least four per event. `era_fingerprint.py`, `notebook_figures.py` and `run3_lj_eff.py` (`gen_acc_mask`) all use it. It passes 99.93% of the 2018 events (8 of 11549 fail, 4 files). In every failing event one lepton's stored pT is exactly 4.000 GeV: nano rounds pT to reduced precision, so a true pT just above 4 lands on the strict cut. The vertex is the stored (smeared) one, whereas the filter read genParticlesForFilter, which is immaterial at 740/960 cm. Earlier versions emulated the filter as pT > 1 GeV, then as pT > 5 GeV, on the first-copy dark-photon leptons (2018 self-pass 92.3%). `lj_eff_real_<era>.json` and `lj_eff_geom_<era>.json` are produced on condor (`condor_lj_eff/`) from all 120 Run 3 chunks per point and 25 v10 files, with this denominator; each record carries the chunk and file counts and the producing commit. `ctau_all_samples.py` measures the proper cτ on every produced sample (180 points x 4 eras, from the LLPNanoAOD GenPart vertices) and writes `ctau_all_samples.csv` and `figures/run3_ctau_all.pdf`.

**Stored precision.** In nano, GenPart_mass is stored with 8 mantissa bits (0.5 GeV steps at 200 GeV, so 34 GeV steps in m/sqrt(x1 x2)) and Generator_x with 14, in both the Run 3 and the 2018 files. The sqrt(s) median is therefore quoted to the storage step, and no width column is given (it would measure storage and line shape). Provenance columns are recorded per process: VtxSmeared, comEnergy and the HLT menu are read from the process that carries them. The generator process's VtxSmeared is compared with the stored GenVtx mean and width (`vtx_pull_*`). In 2018 the only VtxSmeared is in the GEN process (the Realistic25ns13TeVEarly2018Collision values X0/Y0/Z0/SigmaZ = 0.0107682/0.041722/0.035748/3.5 cm, readDB false), while the stored vertex has mean 0.0108/0.0417/0.151 cm and z width 3.20 cm, so its check reads MISMATCH (`vtx_match` False); the Run 3 eras agree. A mismatch never stops the run: it sets `vtx_match` False and prints a WARNING line. No VtxSmeared scenario of the 2018 GEN (CMSSW_10_6_27) or SIM (CMSSW_10_6_17_patch1) release matches the stored vertex (closest: SigmaZ 3.4 cm with the same Z0). The GEN PSet's VtxSmeared parameters are not those of the stored vertex; the smearing step's configuration is not in the file. Every row carries the git commit it was made with (`code_commit`).
